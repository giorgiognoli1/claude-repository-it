Memoria permanente per Claude

Tre strategie combinabili per dare a Claude una memoria che sopravvive a sessioni, provider e cambi di device.

A cura di Giorgio Gnoli · 6 sezioni

Sintesi

Tre strategie combinabili per dare a Claude una memoria che sopravvive a sessioni, provider e cambi di device.

Perché serve

La memoria di sessione di Claude è volatile: nuova chat, nuovi vuoti. Senza memoria permanente devi ogni volta rispiegare chi sei, cosa fai, quali preferenze hai. La memoria permanente trasforma Claude in un collaboratore continuo, non in un collega con amnesia.

Strategia 1 — Skill di onboarding

Crea una Skill chi-sono che descrive te, il tuo lavoro, i tuoi clienti tipo, le tue preferenze. Claude la legge all’inizio di ogni sessione. È il metodo più semplice e funziona subito.

Strategia 2 — MEMORY.md in Obsidian

Mantieni un file MEMORY.md in Obsidian che aggiorni manualmente. All’inizio di ogni sessione Claude carica il file. Il vantaggio: la memoria è editabile, versionata, ricercabile.

Strategia 3 — repository Git

Tutte le tue decisioni, preferenze, glossari e template di prompt salvati in un repo Git. Claude fetcha i file rilevanti all’inizio del task. Vantaggio: versione distribuita, portabile tra device.

Combinazione consigliata

Strategia 1 per chi sei. Strategia 2 per cosa stai facendo ora. Strategia 3 per il know-how di lungo periodo. Insieme coprono tutto.

Cosa non mettere in memoria

  • Niente password.
  • Niente dati sanitari personali.
  • Niente numeri di carta o codici fiscali completi.

La memoria è testo in chiaro, trattala come una mail aperta.
