Claude for Teams: setup completo senza Enterprise

Due strade per portare un team intero su Claude: organizzazione (Chat + Cowork) o un repo GitHub unico con Claude Code. Click-paths e ruoli.

Sintesi

Due strade per portare un team intero su Claude: organizzazione (Chat + Cowork) o un repo GitHub unico con Claude Code. Click-paths e ruoli.

Le due strade

Servono due strade complementari. La prima è più semplice da avviare, la seconda è più scalabile e più economica sul lungo periodo.

Strada A — organizzazione Claude

Configuri Chat e Cowork con ruoli admin e member. Veloce, senza tool esterni.

Strada B — repo GitHub unico

Tutti i membri del team si collegano via Claude Code e condividono prompt, Skill e workflow tramite Git. È una vera libreria condivisa.

Strada A passo per passo

  1. Crea un workspace su claude.ai dal tuo account admin.
  2. Invita i membri via email.
  3. Assegna ruoli: admin (billing, ruoli, workspace), member (uso completo), reader (sola lettura).
  4. Attiva Cowork per i member che ne hanno bisogno.
  5. Definisci una libreria condivisa di Skill tramite la cartella ~/.claude/skills/.

Strada B passo per passo

  1. Crea un repo team-claude su GitHub.
  2. Aggiungi CLAUDE.md con istruzioni condivise, preferenze di coding, standard di testing.
  3. Aggiungi la cartella .claude/skills/ con le Skill di team.
  4. Aggiungi .mcp.json con i connettori condivisi.
  5. I membri clonano il repo, lanciano Claude Code, e hanno immediatamente lo stesso ambiente.

I quattro ruoli operativi

Anche senza Enterprise puoi definire quattro ruoli chiari nel team.

  • Tech Lead — decide architetture, gestisce skill library.
  • Prompt Engineer — mantiene Skill e prompt library condivisi.
  • Reviewer — verifica output, fa QA, applica standard.
  • Operativo — usa gli strumenti, produce deliverable.

Il loop build → push → invite → pull

Sviluppatore lavora in locale, pusha su Git, apre Pull Request, il reviewer approva, l’admin fa merge, tutti fanno pull. La stessa loop che usi per il codice, applicata ai prompt e alle Skill.

Sicurezza

Anche senza Enterprise, privacy e segreti vanno gestiti.

  • Niente API key nei file — usa .env con .gitignore.
  • Niente dati sensibili nei prompt di test.
  • Audit mensile delle Skill caricate nel repo.
