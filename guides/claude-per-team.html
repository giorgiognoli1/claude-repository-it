Team

Claude for Teams: setup completo senza Enterprise

Due strade per portare un team intero su Claude: organizzazione (Chat + Cowork admin) o un repo GitHub unico con Claude Code. Click-paths e ruoli.

A cura di Giorgio Gnoli · Guida operativa, licenza libera con attribuzione.

Le due strade|Strada A — Organizzazione Claude. Configuri Chat e Cowork con ruoli admin e member. Strada B — Repo GitHub unico. Tutti i membri del team si collegano via Claude Code e condividono prompt, Skills e workflow tramite Git. La prima è più semplice da avviare, la seconda è più scalabile e più economica sul lungo periodo.|Strada A passo per passo|1. Crea un workspace su claude.ai dal tuo account admin. 2. Invita i membri via email. 3. Assegna ruoli: admin (gestione billing, ruoli, workspace), member (uso completo), reader (sola lettura). 4. Attiva Cowork per i member richiesti. 5. Definisci una libreria condivisa di Skills tramite la cartella `~/.claude/skills/`.|Strada B passo per passo|1. Crea un repo `team-claude` su GitHub. 2. Aggiungi `CLAUDE.md` con istruzioni condivise, preferenze di coding, standard di testing. 3. Aggiungi la cartella `.claude/skills/` con le Skill di team. 4. Aggiungi `.claude/mcp.json` con i connettori condivisi. 5. I membri clonano il repo, lanciano Claude Code, hanno immediatamente lo stesso ambiente.|I quattro ruoli|Anche senza Enterprise puoi definire quattro ruoli chiari. Tech Lead (decide architetture). Prompt Engineer (mantiene Skills e prompt library). Reviewer (verifica output, fa QA). Operativo (usa gli strumenti, produce deliverable).|Il loop build → push → invite → pull|Sviluppatore lavora in locale → pusha la modifica su Git → apre PR → reviewer approva → admin fa merge → tutti fanno pull e hanno la nuova versione. Stessa loop che usi per il codice, applicata ai prompt.|Sicurezza|Anche senza Enterprise, privacy e segreti vanno gestiti: niente API key nei file, usa `.env` con `.gitignore`. Niente dati sensibili nei prompt di test. Audit mensile delle Skills caricate.
